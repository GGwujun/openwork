# Intent: Task Center 需求智能分析器

## Why

Task Center 当前的工作流程：
1. 从 TFS 拉取"已分析"状态的工作项
2. 用户点击"生成计划"
3. 直接调用 task-automation skill 生成通用计划

**存在的问题：**
1. **不知道改哪里** - 生成的计划没有指向具体代码仓库
2. **没有上下文** - 无法根据需求内容判断技术栈和模块
3. **人工识别慢** - 用户需要手动判断需求涉及哪些仓库
4. **无法处理多仓库** - 复杂需求可能需要修改多个仓库，当前流程不支持

## Scope

### In Scope

1. **需求解析** - 从 TFS 工作项提取关键信息（功能点、技术栈暗示、领域关键词）
2. **仓库识别** - 根据需求内容智能匹配应修改的代码仓库
3. **向导界面** - 3 步骤渐进式向导（需求分析 → 仓库选择 → 计划生成）
4. **生成计划** - 使用 OpenCode 引擎生成 Forge 格式开发计划

### Out of Scope

1. 自动代码实现（保留给 task-automation）
2. 多语言需求分析（当前仅支持中文）
3. 历史数据机器学习（未来版本）
4. 第三方仓库索引服务（当前仅本地 JSON）

## Success Criteria

1. **需求解析准确率** - 能从 80% 以上的工作项中提取有效关键词
2. **仓库识别可用性** - 识别结果置信度 > 0.6 的情况可自动选择
3. **用户体验** - 从点击"生成计划"到看到结果 < 5 秒
4. **人工调整** - 低置信度识别支持用户手动选择仓库
5. **产出生成** - 最终生成标准 Forge 格式（intent + design + tasks）

## Implementation Approach

**内嵌式开发**：直接集成到 `packages/app/src/`，不创建独立 skill

1. JSON 配置文件驱动仓库索引（`src/config/repositories.json`）
2. API 层封装需求解析和仓库识别逻辑
3. Store 层扩展 Task Center 状态管理
4. UI 层实现 3 步骤向导组件

## Risks

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 关键词匹配不够准确 | 中 | 中 | 支持用户手动调整 + 迭代优化配置 |
| JSON 配置维护成本 | 低 | 低 | 配置简单，仓库变动不频繁 |
| 与现有 Task Center 逻辑冲突 | 低 | 高 | 渐进式集成，保留原有按钮功能 |

## Time Estimate

- Phase 1: 基础框架（类型 + API + JSON 配置）- 4h
- Phase 2: Store 扩展（状态管理 + 分析方法）- 4h  
- Phase 3: UI 向导（3 步骤界面 + 交互）- 6h
- Phase 4: 集成测试（端到端验证）- 2h

**Total: ~16 hours**
