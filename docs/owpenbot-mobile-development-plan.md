## 2. 技术决策清单

### 2.1 关键决策点（必须在Week 1确定）

#### 决策1: Expo vs Bare React Native
**建议**: Expo（Managed Workflow）

**理由**:
- ✅ 零配置开发，快速启动
- ✅ 内置推送、生物识别、存储等模块
- ✅ EAS Build简化构建流程
- ✅ OTA热更新（无需审核）
- ⚠️ 原生模块受限（但MVP阶段够用）

**决策**: ✅ 使用 Expo SDK 50+

---

#### 决策2: 状态管理方案
**选项**: 
- A: Context API（简单，但性能差）
- B: Redux Toolkit（经典，但样板代码多）
- C: Zustand（轻量，推荐）
- D: Jotai（原子化，新兴）

**建议**: Zustand + React Query

**理由**:
- Zustand: 极简API，TypeScript友好，无样板代码
- React Query: 处理服务端状态（缓存、去重、后台更新）

**决策**: ✅ Zustand（客户端状态）+ React Query（服务端状态）

---

#### 决策3: 导航方案
**选项**:
- A: React Navigation 6（社区标准）
- B: React Native Navigation（性能更好，配置复杂）

**建议**: React Navigation 6（Native Stack）

**理由**:
- ✅ Expo官方支持
- ✅ 原生导航体验（Native Stack Navigator）
- ✅ 深度链接支持
- ✅ 类型安全

**决策**: ✅ React Navigation 6 + Native Stack

---

#### 决策4: UI组件库
**选项**:
- A: React Native Paper（Material Design，推荐）
- B: React Native Elements（通用）
- C: NativeBase（主题系统强大，但包大）
- D: 自研组件库

**建议**: React Native Paper + 自研业务组件

**理由**:
- Paper提供基础组件（Button、Input、Card）
- 业务组件（ChatBubble、CodeBlock）自研更灵活

**决策**: ✅ React Native Paper + 自研业务组件

---

#### 决策5: 代码高亮方案
**选项**:
- A: react-native-syntax-highlighter（PrismJS，较重）
- B: react-native-highlight-underline-text（轻量，功能少）
- C: 自研（基于react-native-markdown-display + highlight.js）
- D: 原生模块（性能最好，开发成本高）

**建议**: react-native-syntax-highlighter

**理由**:
- ✅ 支持20+语言
- ✅ 主题丰富
- ⚠️ 性能一般（需优化：虚拟化 + 分片渲染）

**决策**: ✅ react-native-syntax-highlighter + 虚拟化优化
